# Legion CLI 优先阶段：客户需求与治理范围

- 记录日期：2026-10-10（Asia/Shanghai）。
- 来源：本次客户对话中的直接要求与逐项澄清；本记录保存需求，不替代后续设计确认、精确执行配置或代码验收。

## 已明确的产品要求

1. 暂缓新增页面工作与既有 Shell 最终验收的后续派发，先完成核心 CLI。旧任务、已运行检查和失败记录保留原样；暂停不是把旧任务标成通过。
2. 第一版必须在真实 npm 安装后运行 `legion` 命令。CLI 路径为交互式项目管理对话，展示完整计划并取得 Human 明确确认，然后执行角色任务及独立验收；仅在源码仓库内能运行不足以交付。
3. 客户只面对一条连续的项目管理对话。产品内固定 ProjectManager、RoleArchitect、Acceptance，并在本版加入 Supervisor；后台系统角色各自保留独立上下文和记忆，其交接对客户无须手动操作或切换角色。真实确认、文件范围、检查及失败结果仍须向客户准确展示。
4. 每个角色具有项目内持久记忆，记录有来源的踩坑、重大决定与用户偏好。普通项目知识和已生效记忆供本项目角色读取；每个角色只能维护自己的记忆，记忆不能授予修改权。用户偏好只在当前项目共享，不跨项目传播。
5. CLI 的模型密钥从当前进程环境取得，不由 CLI 持久保存，不复用或解密桌面 Electron 凭据。角色实际写入继续受边界、任务精确文件清单、当前授权和真实证据约束。
6. Supervisor 应促进已确认计划中互不冲突任务的并行执行；模型建议不得直接产生权限，也不应成为每项任务的新串行审批点。

## 当前治理状态

- [跨角色设计草案](../../docs/roles/ProjectManager/docs/design/2026-10-10_design_cli-first-role-memory-supervisor.md)正在准备；客户尚未确认该草案版本并指示按它修改源码或测试。
- 现有 `bin/legion.mjs` 只提供 `demo`，当前各角色 `boundary.md` 未将该路径授予新 CLI 任务。新源码、测试、包白名单及角色边界须在本阶段精确配置中分配唯一 owner；本记录不授予执行写入权限。
- 本次只在 Governance 范围内记录需求与准备文档路径。旧 Shell `task_ops` 记录没有被本记录改写；恢复旧任务需要由其固定 Supervisor 核对当时的候选、权限与证据。
